# What should RTP improve next?

Share one concrete problem and the change that would make RTP easier to use. Include the device/app where it matters, a sketch or screenshot if useful, and how we would tell whether the change helped.

## Starting points

These are proposals, not promised features or confirmed fixes:

- **Mobile reliability:** test the Android system-bar/cutout and keyboard fix on real phones, including landscape.
- **Windows alpha:** check graphics and actual Arduino serial communication, then prepare a clearly versioned release artifact.
- **Data clarity:** keep sample, cached and server-delivered records easy to distinguish; never imply official clearance.
- **Reporting:** recoverable drafts and clearer review feedback.
- **Access control:** authenticated reviewers and tighter backend authorization before real public moderation.
- **Accessibility and performance:** readable contrast, keyboard use, reduced motion and slower-device behavior, backed by measurements.
- **Documentation:** publish the prepared native Wiki once the publishing connection is restored.

The [current guide](https://github.com/franshessss2/red-tide-ppc/blob/main/docs/community/wiki/Home.md) explains today's capabilities and limits. The Team section still has empty, disabled roster slots; real people/media must be supplied before enabling it.

For a reproducible bug, open an [Issue](https://github.com/franshessss2/red-tide-ppc/issues) with steps and version details. Use **Q&A** for help. Please keep personal details, credentials and device tokens out of public posts.
